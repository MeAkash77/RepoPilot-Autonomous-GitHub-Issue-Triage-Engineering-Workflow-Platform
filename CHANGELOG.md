# Changelog

All notable changes to RepoPilot are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/); versioning is informal until first deploy.

## [Unreleased]

### Added

- Phase 10 Observability & Operational Hardening: two-layer observability stack. (1) Structured logging — `configure_logging()` in `packages/core` with JSONRenderer in production/CI, ConsoleRenderer locally, `merge_contextvars` processor; `RequestContextMiddleware` mints `X-Request-ID` per request and binds it to structlog context; all API + worker logs are JSON with `request_id`, `method`, `path`. (2) OpenTelemetry OTLP push — `init_telemetry(service_name)` in `packages/core` sets up `TracerProvider` + `MeterProvider` → Grafana Cloud via OTLP/HTTP; no-op when `OTEL_EXPORTER_OTLP_ENDPOINT` unset; added to API and worker startup; deps added to `apps/api` and `apps/worker`. (3) Langfuse fix — pinned `langfuse>=2.59,<3` in agent; v4.7.1 broke the v2 SDK API (`client.trace()`/`trace.span()`) causing silent failure on every production triage run; now traces reach Langfuse Cloud. (4) In-app Observability page — `/dashboard/observability` with live p50/p95/p99 latency bar chart, run volume, cost trend, DLQ count, component health tiles (Recharts, `#b6ff3c` theme); four new API endpoints under `/api/v1/observability/` (metrics, health, traces/{run_id}, dead-letter) using `percentile_cont` in Postgres. (5) Public status page — `/status` with component health tiles and last-checked time; no auth required. (6) Deep `/readyz` — real `SELECT 1` DB + Redis `PING`; returns 503 when dependencies down; Fly.io health check uses `/healthz` (liveness, always 200) to avoid routing disruption. (7) LLM fallback + circuit breaker — all five LangGraph routes have `fallback_provider` / `fallback_model` in `models.yaml`; `CircuitBreaker` class in `packages/llm` is Redis-backed, opens after 5 failures for 60 s, half-open probe on recovery; `LLMResponse.used_fallback` tracks activations. (8) Dead-letter alert — `.github/workflows/dlq-alert.yml` cron every 30 min; fails job if DLQ > 5. (9) Load test — `scripts/load-test.js` (k6) + `.github/workflows/load-test.yml` (`workflow_dispatch`). (10) Security scanning — `.github/workflows/codeql.yml` (Python + JS, weekly); `.github/dependabot.yml` (pip/npm/actions, weekly grouped). (11) Coverage — `pytest --cov --cov-report=xml` in CI + `codecov/codecov-action@v4` upload; Codecov badge in README. (12) Grafana dashboard — importable JSON at `infra/grafana/repopilot-dashboard.json` with SLO tiles, latency percentiles, run volume, LLM errors, circuit breaker, log panel. (13) Docs — `docs/OBSERVABILITY.md` with SLOs, endpoint reference, Grafana Cloud setup, Langfuse setup, Loki queries, alerting runbook. (14) Landing page — added OpenTelemetry + Grafana Cloud to stack marquee; new "Watch every run" feature card; eight jobs headline.

- Phase 9 HTTP security hardening: four-layer defense stack added to the API. (1) Rate limiting via `slowapi` with a per-route tier system (webhook 300/min by IP, dashboard reads 120/min by login, mutations 30/min, SSE 10/min), Redis-backed in prod, in-memory fallback in local dev, custom 429 handler with `Retry-After`. (2) IDOR fix — `scoped_repo_ids()` helper resolves a caller's visible repo IDs from `Installation.account_login`; all six dashboard route modules scope queries to the signed-in user; out-of-scope access returns 404 to avoid existence disclosure; local dev stays unrestricted. (3) Request hardening — `SecurityMiddleware` enforces per-path body-size ceilings (2 MB webhooks, 256 KB dashboard), injects HSTS/nosniff/X-Frame-Options/Referrer-Policy/Permissions-Policy on every response, strips the `Server` header, global opaque 500 handler; CORS locked to `WEB_ORIGIN`; `TrustedHostMiddleware` in production; `hmac.compare_digest` for the internal key; Next.js `async headers()` adds HSTS + full CSP tuned for WebGL, Fontshare, GitHub avatars, SSE. (4) Per-installation abuse budget — Redis `INCR` on `budget:{installation_id}:{YYYYMMDD}` with 26 h TTL; over-cap webhooks ledgered `THROTTLED` and never enqueued; GitHub always receives 202. 20 new security tests; 129 total passing.

- Phase 8 deploy & docs: ARCHITECTURE.md with mermaid system + graph diagrams, deploy guide (Neon/Upstash/Railway/Vercel/Langfuse, all free tier), deploy.yml workflow (Railway services + Neon migrations, gated on DEPLOY_ENABLED), README finalized with metrics table and decision rationale.
- Phase 7 MCP server: six tools (pending actions list/approve/reject, triage status, hybrid knowledge search via new /api/v1/search, analytics) over the REST API with stdio + streamable HTTP transports; Claude Desktop setup guide.
- Phase 6 dashboard: dark-first custom theme (no default component-kit look), landing page, overview (cost/latency/approval-rate live precision proxy), keyboard-driven approval inbox (j/k/A/R, optimistic updates), run detail with SSE-streamed node timeline + retrieval/cost breakdown + Langfuse deep link, repo autonomy settings, Recharts analytics; FastAPI gains runs (cursor pagination + SSE stream), repos, and analytics endpoints; server-side proxy keeps the API URL private. NextAuth GitHub login lands with the deploy phase (needs OAuth app credentials).
- Phase 5 evals & security hardening: 26-case red-team suite (25 attacks + benign control) exercising both defense layers deterministically with 100% pass as a hard gate in CI and pytest; comment screening extended to hidden channels (data URIs, HTML comments, tag-block chars); 30-case labeled classification seed dataset + harvest.py for growing it from public OSS repos; eval runner with baseline regression gates (macro-F1 budget 2pts); evals.yml CI workflow; EVALS.md + SECURITY.md.
- Phase 4 actions & HITL: proposed_actions + feedback_events tables, GitHub action executor (labels, comments, duplicate links, assignees, close-as-duplicate) as the single write path, risk x autonomy gate (high risk never auto-executes), runner persists guardrail-approved actions and auto-executes within autonomy, approval-queue API (list pending, approve/edit/reject) recording every reviewer verdict as labeled feedback.
- Phase 3 agent graph: LangGraph triage pipeline (sanitize → retrieve → classify → parallel duplicate/info-gap/code-locator → assignee → compose → guardrail) over typed Pydantic state; LLMRouter with per-node YAML routing (Groq fast, Gemini long-context, single strong-model escalation under a per-run cost ceiling), structured outputs, exact token+cost accounting per node; layered prompt-injection defense (hidden-channel stripping, instruction-pattern detection, autonomy downgrade, output allowlist with comment screening); Langfuse tracing (no-op without keys); triage_runs persistence; versioned prompt registry; triage CLI; ADR-002.
- Phase 2 ingestion & retrieval: knowledge-corpus schema (documents, chunks with pgvector HNSW + generated tsvector GIN, issues), source-aware chunkers (issues with metadata headers + 15% overlap, markdown by headings, code by definition boundaries), Gemini embedding + Cohere rerank providers with deterministic fakes, hybrid search (dense + sparse → RRF k=60 → cross-encoder rerank) preserving per-stage waterfall scores, hash-gated repo indexer, retrieval CLI, recall@k metrics, ADR-001 (pgvector).
- Phase 1 GitHub plumbing: webhook endpoint with HMAC SHA-256 verification (constant-time) and idempotency ledger, GitHub App client (App JWT + cached installation tokens, retrying httpx), arq worker with installation/repo persistence handlers and dead-letter status tracking, SQLAlchemy async models + first Alembic migration, GitHub App setup guide.
- Phase 0 scaffold: uv workspace monorepo (api, worker, 5 packages, evals, mcp-server), typed settings module, health endpoints, arq worker stub, Next.js 15 + Tailwind v4 web app, Docker Compose stack (pgvector Postgres, Redis, api, worker, web), GitHub Actions CI (ruff, mypy strict, pytest, web lint/typecheck/build), pre-commit hooks.
